# サーボモデル検証レポート (単振子)

`ServoJointModel` (摩擦・バックラッシモデル) の物理的妥当性を、単振子で検証した結果のまとめです。テスト本体は `Assets/Tests/ServoModelTests/ServoPendulumTests.cs` にあり、いつでも再実行できます。

## 検証環境

- Unity 6000.3.21f1 / PhysX ArticulationBody / Fixed Timestep 0.02 s (50 Hz)
  (6000.2.7f2 でも同一結果。剛性の選び方は下記「伝達剛性の選び方」を参照)
- リグ: 固定ベース + revolute 1軸の振子
  - 質量 m = 0.2 kg、重心距離 L = 0.2 m (最大重力トルク mgL ≈ 0.39 N·m)
- サーボモデルのパラメータ:

| パラメータ | 値 |
|---|---|
| サーボPD (Kp, Kd) | 20 N·m/rad, 0.5 N·m/(rad/s) |
| トルク上限 | 2 N·m |
| モータ慣性 Jm (ギア換算) | 2×10⁻³ kg·m² |
| 静止摩擦 τ_s / 動摩擦 τ_c | 0.15 / 0.08 N·m |
| Stribeck速度 ω_s / 粘性 σ_v | 0.1 rad/s / 0.005 N·m/(rad/s) |
| ガタ全幅 (2b) | 0.0174 rad (約1°) |
| 伝達剛性 K / ダンピング D | 50 N·m/rad / 0.5 N·m/(rad/s) (摩擦曲線のみ K = 0.2、理由は後述) |

各テストのアニメーション (GIF) では、実スケールでは見えないガタ (±0.5°) を「ピン (モータ側) とスロット (関節側)」の拡大模式図で可視化しています。ピンがスロットの歯面に接触して係合すると、接触側の壁が濃い青になります。

本文の数値も図版も、現在の設定 (K = 50 / 摩擦曲線のみ 0.2) で取り直したものです。
図は `python3 docs/tools/plot_servo_validation.py` で CSV から再生成できます
(節末の「再実行方法」を参照)。6 章の `runtime_validation.png` もデモ側リポジトリで
取り直しました (生成手順は同章に記載)。

## 1. ヒステリシス (バックラッシの基本挙動)

無重力・負荷側摩擦ありで ±0.3 rad の低速三角波指令を与え、指令-応答平面を観察。

![hysteresis_anim](images/servo-model/hysteresis_anim.gif)

指令が反転するたびに、ピンがスロット内を横断してから反対側の歯面で再係合する様子 (中央) と、その間ジョイントが動かず応答平面 (右) にループが描かれる様子がわかります。

![hysteresis](images/servo-model/hysteresis.png)

- 指令反転のたびにガタ幅ぶん応答が遅れ、レンズ形のヒステリシスループが形成される
- **ループ幅 (cmd=0): 0.0270 rad** — 名目ガタ幅 0.0174 rad の約155%。ガタに加えて
  負荷側摩擦 0.05 N·m による伝達たわみと PD 垂れ (2×0.05/Kp = 0.005 rad) が乗る

## 2. 重力跨ぎ (負荷トルク反転時のガタ飛び移り)

重力下で −0.6 → +0.6 rad を一定速度 0.15 rad/s で通過。**指令は単調のまま**、最下点 θ=0 で重力トルクの符号だけが反転する。指令側のフィルタでは原理的に再現できない現象の確認。

![gravity_crossing_anim](images/servo-model/gravity_crossing_anim.gif)

振子が最下点 (t≈4.0 s) を通過すると、指令は動き続けているのに、ピンが左歯面から右歯面へ乗り移り (中央)、Δ (右下) が符号反転します。

![gravity_crossing](images/servo-model/gravity_crossing.png)

- 伝達たわみ Δ (2段目) が跨ぎを挟んで **−0.0051 → +0.0126 rad へ遷移** — ピンが歯面を乗り移る
- **実際に伝達されたトルクは t = 4.12 s、θ = +0.004 rad で反転** — 負荷トルクの符号が変わる
  最下点そのもの。保持中は −0.198 N·m で重力トルクと一致する
- モデルが記録する Δ のゼロクロスはこれより早い (t ≈ 2.3 s)。Δ はステップ**開始時**の負荷位置に
  対して評価しているためで、後述「伝達剛性の選び方」の K·ω·dt のバイアスそのもの。
  バイアスが乗らないのは伝達トルクのほう
- 乗り移りの前後で関節速度 (最下段, t ≈ 2.6 s) に小さな乱れ (ガタの「ガクン」) が現れる

## 3. 摩擦-速度曲線 (Stribeck摩擦の再現精度)

無重力・ガタなしで一定速度追従させ、定常偏差から摩擦トルクを逆算する。回転子の運動方程式は
`Jm·dωm/dt = τ_servo − τ_f − τ_trans` なので、定常では
**τ_f = Kp·e + Kd·(ω−ωm) − τ_trans**。伝達項は無視できない: 負荷を等速で引きずる間、
不感帯の引数はちょうどその 1 ステップぶん古く、回転子は K·ω·dt 相当の残差を負う。
この項を落とすと ω = 2 rad/s で摩擦を 44% 過大に見積もる。さらにこのテストは
摩擦を単離するのが目的なので、ガタを 0 にするのと同じ理由で伝達剛性も K = 0.2 まで下げる
(K = 2 のままだと項を入れても 7.7% 残る)。

![friction_curve](images/servo-model/friction_curve.png)

| ω [rad/s] | 計測 [N·m] | モデル [N·m] | 誤差 |
|---|---|---|---|
| 0.05 | 0.1348 | 0.1348 | +0.0 % |
| 0.10 | 0.1063 | 0.1063 | +0.1 % |
| 0.20 | 0.0822 | 0.0823 | −0.1 % |
| 0.50 | 0.0823 | 0.0825 | −0.2 % |
| 1.00 | 0.0847 | 0.0850 | −0.4 % |
| 2.00 | 0.0893 | 0.0900 | −0.8 % |

設定した Stribeck 曲線 (すべり出しの山 → クーロン摩擦 → 粘性の右肩上がり) を **全域で誤差0.8%以内** で再現。

## 4. 重力下の位置保持 (固着・チャタリング)

重力下で 0.25 rad をステップ指令で保持。静止摩擦モデルの数値実装で典型的に問題になる stick-slip チャタリングの有無を確認。

![stiction_hold_anim](images/servo-model/stiction_hold_anim.gif)

過渡振動の間はピンがスロット内を行き来し、静定後は片側歯面に係合したまま完全に静止します (チャタリングがあればここでピンが振動し続けます)。

![stiction_hold](images/servo-model/stiction_hold.png)

- 過渡振動の後、完全に静止 (最後の 2 秒間、関節位置はビット単位で不動。位置の標準偏差 ~10⁻¹⁶、
  ステップあたりの変位は厳密に 0)。なお `jointVelocity` はこの間も約 0.08 rad/s を報告するが、
  これはドライブが効いている関節で常に乗るゴミであり、チャタリングではない
- 定常誤差 0.0139 rad (≈0.8°) — 摩擦の固着 (≤τ_s/Kp) + ガタ + PDの重力垂れの合計として妥当な範囲
- モータはKarnopp固着で停止し、保持トルクは伝達ばね経由で正しく重力と釣り合う

## 5. スティックスリップ (固着すべり)

Stribeck 膝 (ω_s = 0.1 rad/s) より遅い 0.07 rad/s で重力に逆らって持ち上げる。
回転子は滑らかに滑れず、Karnopp 条件で速度がちょうど 0 に固定され → 手前のコンプライアンスが
巻き上がり → 離脱トルク τ_s を超えて飛び → また固着、を繰り返す。

![stick_slip_anim](images/servo-model/stick_slip_anim.gif)

![stick_slip](images/servo-model/stick_slip.png)

*(左右で掃引速度は同一。違うのはサーボ減衰 Kd だけ)*

- **持続するかどうかを決めるのはサーボ減衰**。検証パラメータの Kd = 0.5 は回転子を
  過減衰にする (ζ = Kd/(2√(Kp·Jm)) = 1.25) ため、静止からの離脱で一度跳ねたあとは
  滑らかに滑る (離脱 **1 回**)。Kd = 0.02 まで下げると掃引の全域で限界サイクルが
  持続する (離脱 **148 回**、モータ速度は 0 と 0.25 rad/s の間を往復)
- ジャダー振幅 (重力たわみのトレンドを除去後) は **0.0015 rad**。回転子が巻き上げられる
  コンプライアンスで決まる境界 (τ_s−τ_c)/(Kp+K) = 0.0010 と
  (τ_s−τ_c)/K_series = 0.0049 の間に収まる (K_series = 1/(1/Kp + 1/K))。
  Kd = 0.5 側は 0.0003 rad で、5 倍小さい
- よく減衰した実機サーボがジャダーしないのはこの依存性そのもの

## 6. ランタイム (ビルド済みプレイヤー) での検証

エディタ上の単振子テストとは独立に、ビルド済み Linux プレイヤーへ URDF から
スポーンしたロボット (理想サーボとの並置デモ、[Unity_ROS2_sample の
servo_demo_description](https://github.com/hijimasa/Unity_ROS2_sample)) でも
主要現象を実測しています:

![runtime_validation](images/servo-model/runtime_validation.png)

- **バックラッシ** (左): 理想関節を基準にした偏差が、重力が押し付ける側の
  歯面に ±45 mrad (= 設定ガタ全幅 0.09 rad の半分) で張り付き、最下点通過で
  ギャップを横断して反対歯面へ乗り移る。上り/下りの枝の分離がヒステリシス
- **スティックスリップ** (右): 低速スイープ (約 0.1 rad/s) 中のジャダーは
  **14 mrad p-p**。回転子が巻き上げるコンプライアンスで決まる境界
  (τ_s−τ_c)/(p_gain+K) = 8 mrad と (τ_s−τ_c)/K_series = 34 mrad の間に収まる
  (実機側パラメータは p_gain = 4.0、K = 2.0、τ_s−τ_c = 0.045 N·m)。
  ただし個々の固着→離脱は約 45 周期/秒で、`joint_states` の 100 Hz が
  分解限界なので個別のイベントとしては見えない (振子テストの
  5 章は 50 Hz の物理ステップを直接見ているので分解できる)

### 伝達剛性の選び方 (2026-08-08 更新)

かつてこの節には「`-batchmode -nographics` では 4 テストとも失敗する。原因は xDrive の
単位補償を `#if UNITY_EDITOR` で切り替えているためで、対話実行なら通る」と書いてありました。
**この記述は実験で否定されました。**

- 実行モードは無関係でした。`-nographics` を外しても、`-batchmode` ごと外して GUI の
  Test Runner で走らせても、有効数字 7 桁まで同一の失敗値になります。Unity 6000.2.7f2 でも同じです
- xDrive の単位も無関係でした。バッチ実行でも stiffness は N·m/rad のまま (比 1.16)、
  targetVelocity は度/秒として正しく変換されます
- 真の原因は **`ArticulationBody.jointVelocity` が、xDrive の駆動による関節の運動を
  反映しないこと**でした。素のドライブで 0.15 rad/s の掃引中に報告される値は −0.008 rad/s です。
  一方ドライブのない自由関節では誤差 4e-5 で正確なので、自由落下で確かめると見逃します。
  モデルはこの値を負荷位置の外挿に使っていたため、歯面判定が反転して発散していました

`ServoJointModel` は `jointVelocity` を読まなくなり、負荷位置の外挿も廃止しました。
残るのは離散化そのものに由来する次の制約です。

**不感帯の引数はステップ終端の負荷位置を必要とし、遅れのない推定値は存在しません。**
この誤差は関節に **K·sech²(δ/b)·ω·dt** のトルクとして現れます。したがって伝達剛性は
2 つの相反する条件に挟まれます。

- **ガタが支配的であること** (バックラッシのテストが意味を持つ): `K > τ/b`
- **離散化誤差が無視できること** (定量的に一致する): `K·ω·dt ≪ 分解したいトルク`

| テスト | τ [N·m] | ω [rad/s] | 下限 | 上限 | 窓 |
|---|---|---|---|---|---|
| GravityCrossing | 0.22 | 0.15 | K > 25 | K ≪ 73 | 25〜73 |
| Hysteresis | 0.05 | 0.075 | K > 6 | K ≪ 33 | 6〜33 |
| FrictionCurve | 0.09 | 2.0 | ガタ未使用 | K ≪ 1 | 低いほど良い |

`ServoPendulumTests` はバックラッシ系を **K = 50 N·m/rad**、摩擦曲線だけを
**K = 0.2 N·m/rad** で回します (摩擦曲線は掃引が 13 倍速いため窓が重ならない。もともと
ガタを 0 にして摩擦を単離しているテストなので、伝達剛性も同じ理由で下げる)。以前の
K = 400 はどの窓からも外れており、さらに離散安定限界 (K ≈ 200〜250) も超えていました。
実機の servo_demo が使う K = 2 は十分内側です。

**`jointVelocity` はテストの判定にも使わないこと。** ドライブが効いている関節では
約 0.08 rad/s のゴミが常に乗ります。`StictionHold_NoChatter` はこれを「チャタリング」として
検出していましたが、同じ 2 秒間の関節位置はビット単位で不動でした (素のドライブでも
同じ 0.08 が出ます)。判定は位置の有限差分で行います。

これらは `Assets/Tests/ServoModelTests/ServoEnvironmentProbe.cs` の診断テストで
いつでも再測定できます。ビルド済みプレイヤー側の挙動は
[サービス適合性テスト](Service-Conformance-Test-ja.md) の servo_demo プロファイルで
継続的に検証しています。

## 実装上の知見 (開発メモ)

1. **ギャップ内で伝達剛性をゼロにしてはいけない**: 歯面衝突が物理ステップ内で起こると無抵抗で貫通し、次ステップで巻き上がったばねが再構成されてエネルギーが注入される (数値的な反発係数 >1)。剛性は常時一定とし、バックラッシはドライブ目標のアンカー位置 (θm − b·tanh(Δ/b)) に持たせる
2. **xDrive の単位系**: target/targetVelocity は度だが、stiffness/damping は **ラジアン換算誤差に掛かる (N·m/rad)**。`driveForce` の実測で確認済み
3. **負荷位置を外挿してはいけない**: 陰的ドライブは K·(target − θl) をステップ終端の θl に対して解くので、こちらで θl + ωl·dt を予測すると二重計上になる。しかも予測に使える速度は 1 ステップ古い有限差分しかなく、剛性 K が掛かる項に遅れを入れることになって発振する (保持テストで K = 100 から発散、外挿をやめれば K = 800 まで安定)。代償として不感帯の引数が 1 ステップぶん古くなり、これが K·sech²(Δ/b)·ω·dt のトルク誤差として残る — これがモデルの有効範囲を決める
4. アクチュエートされる関節では **ArticulationBody をスリープさせない** (`sleepThreshold = 0`)。モータ固着中は目標が動かないため、スリープすると巻いたばねごと凍結する
5. **エディタとビルド済みプレイヤーで xDrive の単位が異なる**: Linux プレイヤーでは stiffness/damping/forceLimit が名目値の π/180 倍で作用する (素のドライブの静的たわみから実測)。エディタは名目通り (知見2はエディタでの実測)。ServoJointModel は環境条件付きで補償する
6. **`jointVelocity` は環境を問わず信用しない**: xDrive が駆動している関節では、その運動がまったく反映されない。素のドライブで 0.15 rad/s 掃引中の報告値は −0.008 rad/s、静止保持中は約 0.08 rad/s のゴミが乗る。ドライブのない自由関節では誤差 4e-5 で正確なので、自由落下で確かめると見逃す。モデルもテストも位置の有限差分を使うこと
7. **リミット面で静止した関節は固着する**ことがある (ドライブトルクに無反応)。ランタイムでのリミット書き換えによる解除は位置スナップ (数百 rad/s) を誘発するため不可。重力静止姿勢をリミットから離す設計 + 仮想回転子のリミットクランプで予防する
8. **スポーン直後の関節状態はリセットする**: ランタイム構築とルートのテレポートは関節座標へのステップ入力になり、数百 rad/s の過渡速度が注入される (SimulationControl 側で対処済み)
